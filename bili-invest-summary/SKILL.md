# B站投资视频汇总

自动抓取B站投资类UP主视频字幕，生成单条摘要与跨UP主分析报告。

## 依赖

- `opencli` CLI，需 `bilibili user-videos`、`subtitle`、`summary`、`video` 命令可用
- `opencli browser`（Chrome bridge），用于第 3 步浏览器逐个打开视频；不可用时跳过该环节，不影响报告生成

## 配置

UP主列表维护在 `data/uplist.yaml`。用户可指定：
- 特定UP主名（匹配 uplist.yaml 中的 name 字段）
- 分组标签（如"投资组"= tags 含 `invest`）
- 不指定则抓取全部UP主

## 工作流程

### 1. 读取配置

读取本 Skill 目录下 `data/uplist.yaml`，按用户指定范围筛选目标UP主。

### 2. 获取视频列表

对每个目标UP主，**优先用 uid 精确抓取**，回退到搜索：

```bash
# 优先
opencli bilibili user-videos <uid> --limit 10 -f json
# 回退（uid 为空时）
opencli bilibili search "<UP主名>" --limit 10 -f json
```

筛选**当天**发布的视频。当天无视频则取**昨日**。两天都无则告知用户并结束。

**特殊规则**：若UP主配置中指定了 `limit: 1`，则当天只抓取最新的一条视频。

### 3. 逐视频处理：抓字幕 → 开标签暂停

对每条视频**串行**执行 (a)(b) 两步，做完一条再处理下一条：

**(a) 抓取字幕与总结**

```bash
opencli bilibili subtitle <BV号> -f plain
opencli bilibili summary <BV号> -f json   # 官方AI总结，作为补充
```

字幕为空时仅用 summary 结果。

**(b) 立即为该视频开标签并暂停**，按下方「浏览器开标签规程」执行。

把开标签并入逐视频流程，字幕抓完时所有标签已就位暂停，报告一保存即可观看，浏览器环节不再拖在报告后面拉长总时长。

### 4. 单条视频摘要

基于字幕内容生成每条视频摘要：

```markdown
### [视频标题](URL)

- **UP主**：xxx
- **发布时间**：YYYY-MM-DD
- **播放量**：xxx

**核心观点**：
- 要点1
- 要点2

**提及板块**：板块A、板块B
**策略方向**：看多/看空/观望 + 简述
**风险提示**：如有
```

### 5. 跨UP主分析

所有单条摘要完成后，综合分析：

```markdown
## 投资机会

AI根据整体语境分析：UP主明确看多、推荐关注、**无负面提示**的具体板块/指数。

**AI分析要点：**
- 理解UP主的真实意图：是否推荐关注、是否有隐含风险
- 排除有负面提示的：警惕风险/不建议追高/可能面临压力/高溢价/需等待回调等
- 排除中长期看多但短期观望的：两边都不列
- 只列具体板块/指数：如黄金、煤炭、电力、恒生科技、科创50、纳指ETF、AI应用软件等
- 不列抽象概念：大盘低点、A股等

**表格列顺序：**板块 | 机会类型 | 备注 | 提及UP主

| 板块 | 机会类型 | 备注 | 提及UP主 |
|------|---------|------|----------|

## 风险提醒汇总

AI根据整体语境分析：UP主明确建议"不要进入""离场""谨慎""观望离场"的板块。

**AI分析要点：**
- 理解UP主的真实建议：是否明确建议离场或持谨慎态度
- 只列明确建议离场的：不要进入/离场/清仓/谨慎/观望离场/等反弹卖出/不要开新仓/先减仓/可能面临压力等
- 不列客观事实描述：某板块跳水了/跌了X%/破位（无明确建议）
- **冲突检查**：同一板块已列入投资机会时，不列入风险提醒（避免自相矛盾）

**多条合并**：同一板块有多个UP主提醒时，合并成一条，注明"来源：多位UP主"。

- 风险点（来源：UP主）

## 观点共识

AI根据整体语境分析：不同UP主对**同一板块/指数**提出**相同方向**的观点。

**AI分析要点：**
- 识别同一板块的不同表述：如"科创50""半导体""科创芯片"视为相关板块
- 判断观点方向是否相同：观望进场与观望进场=相同；观望进场与观望离场=不同；离场与清仓=相同
- 单独"观望"需根据上下文判断是进场还是离场
- 只列多方UP主观点一致的板块；观点方向不同或只有一个UP主提及的不列入

| 观点/板块 | 提及UP主 | 共识方向 | 备注 |
|----------|---------|---------|------|

## 策略对比

| UP主 | 主要策略 | 核心逻辑 |
|------|---------|---------|
```

### 6. 输出报告

#### 对话展示

```markdown
# B站投资视频日报 YYYY-MM-DD

共 X 位UP主、Y 条视频。

[单条摘要]

[跨UP主分析]
```

#### 保存文件

保存到 `B站投资日报/YYYY-MM-DD.md`（仓库根目录），纯 Markdown，无 YAML frontmatter。标题即 `# B站投资视频日报 YYYY-MM-DD`。

保存后在对话里告知：视频标签已在第 3 步逐个开好并暂停，可逐个标签切换观看。

## 浏览器开标签规程（第 3(b) 步执行）

报告保存前在浏览器中为每个视频开一个标签页并立即暂停：用户粗读文档的同时，直接逐个切换标签看视频，不用再点文档里的链接。

**必须串行处理：开一个 → 视频元素一出现立刻暂停 → 确认 → 才轮到下一条视频。** 绝不能先批量全开再逐个暂停——后台标签从打开起就一直在播放，轮到它时已经播了很久。

**对每个视频（`tab new` 返回的 `page` id 必须保存，后面所有 eval 都要显式 `--tab` 定向）：**

```bash
opencli browser bili-summary tab new "<视频URL>"
# → 记下返回的 page id 作为 <tid>
```

轮询循环（每 0.6s，上限 15s），全部带 `--tab <tid>`：

```bash
opencli browser bili-summary eval 'JSON.stringify({u:location.href,n:document.querySelectorAll("video").length,p:[...document.querySelectorAll("video")].every(v=>v.paused)})' --tab <tid>
```

- **确认条件（缺一不可）**：返回的 `u` 包含该视频的 BV 号 **且** `n>0` **且** `p=true`。URL 校验是防错位的关键——不校验 URL 时，eval 偶尔会落到上一个标签（它本来就是暂停的），返回"已暂停"造成误报，新标签就一直播放
- 若 `u` 匹配且 `n>0` 但 `p=false`：执行暂停 `document.querySelectorAll("video").forEach(v=>v.pause())`（同样带 `--tab <tid>`），继续轮询
- 确认暂停后等 1 秒，对同一 `<tid>` 再查一次状态；若又变回播放中（加载途中播放器自动开播）就再暂停一次
- 确认通过即视为该视频**完成**，之后不再对它做任何终检复检（批量终检正是 2026-09-22 桥重启的导火索，见下方纪律）
- 单视频 15s 内未能确认：跳过并在报告末尾注明。**绝不为同一 BV 号开第二个标签重试**——重复标签就是这么来的

**桥稳定性纪律（实测教训，2026-09-22 桥会话中途重启 → 误判全量重开 → 9 个重复标签）：**

- **任何两次 opencli browser 调用之间必须间隔 ≥1 秒**，批量循环必须带 `sleep 1`。实测 9 个请求连发（无间隔终检）直接把桥打死，触发会话重启
- 识别桥重启：报错 `Target tab ... is not part of the current browser session`。此时**不要认定旧标签已被关闭**——会话级 `tab list` 只显示当前会话开的标签，旧标签多半还挂在 Chrome 里
- 桥重启后的正确处置：恢复会话（必要时 `unbind` 再 init），**按 BV 号对账**：已有确认标签的视频跳过，只补开缺失的。失联的旧标签**不要**强行 select/close——会报 `Page is not in the automation container`，实测全数失败；在报告末尾注明"有 N 个失联标签需手动关闭"即可
- **不要**依赖"默认当前标签"隐式定位（不用 `--tab` 的 eval 目标可能对不上刚开的标签，这正是"有的暂停有的没暂停"的根因）
- **不要**注入定时器/守望器，**不要**固定 sleep 6s 等加载——实测前者不可靠、后者浪费时间
- **不要**用点击暂停——合成点击对播放器暂停层不生效
- 会话名固定 `bili-summary`；若会话绑定在用户标签上 `tab new` 会被拒（`bound_tab_mutation_blocked`），先 `unbind` 再开
- eval 返回为单层 JSON；解析失败时打印原始输出排查，不要静默跳过
- opencli browser 不可用或桥持续异常时：跳过剩余标签工作（第 3 步只做抓字幕），报告末尾注明"浏览器打开失败，请点击文档链接"。**浏览器问题永远不得阻塞或推迟报告生成**
- 结束时**保留标签不关闭**，留给用户观看

## 注意事项

- opencli 命令失败时标注"获取失败"，继续处理其他视频
- 严格基于字幕和AI总结生成，不编造内容
