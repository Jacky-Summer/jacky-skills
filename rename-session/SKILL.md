# 会话起名

产出一行会话名 `MMDD | 类型 | 主题`，适用于 ZCode、Codex 等会话列表，交给用户粘贴。只产出名称文本，绝对不要修改项目名称。

## 步骤

1. **日期**：会话创建当天的月日，四位 `MMDD`（跨天的长会话仍用创建日）。
2. **类型**：从下方清单（闭集）中选一个。判据是会话的主要产出，两者都沾时看最终交付了什么。
3. **主题**：10–20 字名词短语，最长 25 字，不含 `|`。写清「对什么、做什么/产出什么」，补上限定词（哪个项目、哪一块、什么结果），细节优先于简短。
4. **输出**：一行 `MMDD | 类型 | 主题`，如 `0909 | 研究 | 会话命名类型体系调研`。类型无法判断时保留原名，并按「清单演进」提名。

## 类型清单

| 类型 | 判定 |
|------|------|
| 功能 | 新增能力或代码 |
| 修复 | 解决缺陷 |
| 调试 | 定位问题原因，尚未解决 |
| 优化 | 改性能或体验 |
| 重构 | 行为不变的结构整理 |
| 测试 | 写测试、补用例、修测试 |
| 样式 | UI 外观与布局调整 |
| 迁移 | 框架、依赖、数据的迁移升级 |
| 部署 | 构建、发布、CI/CD 排障 |
| 配置 | 本地工具、环境、技能搭建 |
| 设计 | 方案、交互、视觉设计 |
| 评审 | 审已有代码或方案，给出意见 |
| 文档 | 写说明、教程类内容 |
| 探索 | 在自己的代码库/知识库里翻找验证 |
| 研究 | 对外查资料回答问题 |
| 学习 | 跟课或导师式学习，产出是理解 |
| 笔记 | 单一来源的捕捉与蒸馏 |
| 汇总 | 多个信息源聚合成摘要 |
| 写作 | 对外发布文章 |
| 咨询 | 只讨论与决策，不出产物 |
| 定时 | 定时自动化任务的执行记录 |

## 清单演进

清单是闭集，归类只从上表选取。无法归类时保留原名，同时提名一个两字新类型和一句判定，经用户确认后加入上表。同类提名出现第二次时，提醒用户扩清单。
